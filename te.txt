Pinpointing the hidden catch block that masks failed requests.
The cause is in request.js, in iwxPosts2:

js
}).catch((reason) => {
  return reason;      // <-- error gets RETURNED, not rejected
});
When the insert request fails (HTTP 500/404/400, timeout or Network Error), this turns the failure into a successful result whose value is the Error object. So in submitForm, the original code's .then((res) => { ... this.engFormCreateLog(); }) runs as if the insert succeeded. The .catch in submitForm never fires either, so the failure is hidden twice.

The backend could also have returned HTTP 200 with IsOk set to a failure value. Your code ignores that case as well. Either way, the insert is rejected, nothing is saved, and the sign-flow check then finds no row.

Fix: update the helpers in submit.vue

The submitForm I gave you last time stays, apart from the two changes below. Replace isInsertOk and add errText:

js
    isInsertOk(res) {
      if (!res || res instanceof Error) return false;   // request failed (swallowed by request.js)
      const flag = res.IsOk !== undefined ? res.IsOk : res.IsOK;
      const f = String(flag).toLowerCase();
      return f === '1' || f === 'true';
    },

    errText(res) {
      if (!res) return 'no response from server';
      if (res instanceof Error) {
        const r = res.response;                          // axios error with an HTTP response
        return r
          ? 'HTTP ' + r.status + ': ' + JSON.stringify(r.data).slice(0, 200)
          : res.message;                                  // "Network Error", "timeout of ...ms exceeded"
      }
      return res.Msg || res.msg || JSON.stringify(res).slice(0, 200);
    },

        if (!this.isInsertOk(res)) {

        }
The temporary INSERT: toast should also use this.errText(res). Now the failure shows the HTTP status and the server's message, or the backend's Msg. Other problems in request.js

Special characters in unencrypted values. dealPostParams replaces only the first = and the first & in each value. It also doesn't encode %, +, # or line breaks. A Reason such as R&D & QA, one containing % or +, or one with an Enter key press (it is a 3-row textarea) can corrupt inputString and the backend rejects it. Today's reason has none of these, so this isn't today's failure. To be safe, clean the values in submitForm before building body:
js
   const clean = v => String(v).replace(/[\r\n]+/g, ' ').replace(/%/g, '%25')
     .replace(/&/g, '%26').replace(/=/g, '%3D').replace(/\+/g, '%2B').replace(/#/g, '%23');
   // use: body[i.api] = clean(value)
This assumes the gateway URL-decodes inputString values, which the first-occurrence escaping suggests. Verify with a Reason containing &, and check the saved text in the table.
2. Concurrent requests mix up headers. The request interceptor overwrites each call's apiID and userKey with module-level globals. Two iwxPosts2 calls fired in the same tick both use the last call's keys. This happens on page load, where GetBasecodeinfo and getUserBaseInfo start together. It isn't the insert problem, because the insert runs alone. It can cause wrong data on load, such as missing application types. The fix is to delete the if (apiID != "" && userKey != "") {...} block in the interceptor, since every call already passes its own config.headers. Test that change on other pages first, because they share the file.
